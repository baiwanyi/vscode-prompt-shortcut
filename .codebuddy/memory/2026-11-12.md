# 2026-11-12

## 新增环境维护类工具命令（重启 ESLint / 重启 TS / 重载窗口）

- 三条命令只做「本扩展命令 → VS Code 命令」转发，不发送提示词、不读选区、不依赖 CodeBuddy：
  `baiwanyi.prompt.restartEslint` → `eslint.restart`（dbaeumer.vscode-eslint，已核对 3.0.34 清单）、
  `baiwanyi.prompt.restartTsServer` → `typescript.restartTsServer`、
  `baiwanyi.prompt.reloadWindow` → `workbench.action.reloadWindow`。
- 入口三处：命令面板（category「提示词快捷方式」）、右键「快捷命令」子菜单 `9_tools` 分组、
  侧边栏底部常驻工具条（`ToolBar`，元数据由宿主随 state 下发）。
- 分层沿用右键动作的三段式：`toolActions.ts`（表：命令 / 委派 / 缺失提示 / isDetached）→
  `runToolAction.ts`（转发编排）→ `registerToolActions.ts`（遍历注册）。
- 关键约束：命令注册是惰性的，不做 `getCommands()` 预检，统一以 `executeCommand` 抛错判定「目标未安装」；
  重载窗口走 `isDetached` 脱手执行（Promise 永不 resolve，不能 await）。
- 协议：`WebviewToHostMessage` 增 `runTool`，`PromptStatePayload` 增 `tools`；宿主按表校验 id，未知名直接提示。
- 图标：新增独立 `ToolIconKey`（restart / reload），不复用 `PromptIconKey`，避免污染提示词图标选择器。
- 验证：`pnpm run typecheck`、`pnpm run lint` 通过；`pnpm run compile` 产物正常（extension.js 25.7kb）。
  `pnpm run verify` 的 Prettier 环节报既有格式问题：`PanelHeaderCapacity.tsx`、`PromptItem.tsx`（本次未改动，未处理）。

## Tooltip 字体对齐 VSCode（同日三次调整）

- `styles.css` 增加未分层的 `[data-slot='tooltip-content']` 规则：字体族取 `--vscode-font-family`、
  字号取 `--vscode-font-size`（默认 13px，替代组件自带 `text-xs` 的 0.85 倍）、字重 400、行高 1.5。
- 宽度一并收敛：`max-width: min(20rem, calc(100vw - 16px))` 配合 `white-space: normal` 与
  `overflow-wrap: anywhere`，替换组件自带的固定 `max-w-xs`——窄侧边栏下 320px 会越过面板右缘被裁。
- 不改 `ui/tooltip.tsx`（shadcn 托管源码，CLI 覆盖会丢失），沿用项目既有的「layer 外规则覆盖组件内置档位」做法
  （与 input 字号规则同一分区）。

## Tooltip 自动收起（同日四次调整）

- 新增 `webview/hooks/useAutoDismissTooltip.ts`：受控 `open` + 打开后 3000ms 自动关闭，关闭与卸载时清理定时器。
- 应用范围：`ToolItem`、`PanelHeaderCapacity`、`PanelHeaderConnection` 三处 Tooltip 统一改为受控开合。
- 原因：Radix 只在指针离开触发元素时关闭，鼠标停在原处时提示会长期遮挡面板内容。
- 顺带按 Prettier 格式化 `PanelHeaderCapacity.tsx`（原有超长行，即先前遗留的两处既有格式问题之一）。
- 验证：`typecheck` / `lint` / `compile` 通过，改动文件 prettier 无差异。
